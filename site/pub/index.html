Publish — sign a content bundle, entirely in your browser
Browser not supported ✕ missing crypto

This page signs bundles with the browser's own crypto — WebCrypto Ed25519 and CompressionStream — and this browser does not provide both. Recent versions of Chrome (137+), Firefox (129+), and Safari (17+) do. Nothing is downloaded to work around it: a page that handles a signing key loads no third-party code.

1 · Signing key no key loaded

The key lives in this tab's memory — unless you choose remember once it's loaded, nothing is stored in the browser and closing the tab forgets it. Keep the key file either way; it is the one credential that can publish to your site.

Public key — paste into config > publish as publish_key

This browser now holds the key as a non-extractable signing key: pages on this site can sign with it but cannot read it out — not even this one. It is not a backup — clearing this browser's site data deletes it, and only the key file restores it.

This key has no copy outside this browser until you download it. The file is a standard Ed25519 private key (PKCS#8 PEM, readable by openssl). Anyone holding it can publish to any site configured with the public key above; without it, no one can — including you. There is no recovery.

2 · Site folder no folder chosen

Pick the folder whose contents should become the site — the folder that holds your index.html. Files are read here in the browser; nothing is uploaded anywhere. Or start with the demo site: Servette's self-test page as your front page until you replace it.

Then, wherever the pair is hosted

Upload both files side by side — any static host works — so that the signature resolves at the bundle's own URL plus .sig. Then, in your Servette's shell:

config publish   # paste the bundle URL and the public key above
pull             # fetch, verify against your key, swap the content in
restore-site     # one step back, if you ever want the previous content

Everything above happens inside this tab: the page talks to no other site — its only request is fetching its own self-test page from this same site when a bundle includes it — and it stores nothing in the browser unless you ask it to remember your key, and then only a signing handle that cannot be read back out. It only ever produces files you choose to download — your server pulls content when you run pull, and never accepts a push. Served by Servette — The Simple, Secure, Static-Site Server.
